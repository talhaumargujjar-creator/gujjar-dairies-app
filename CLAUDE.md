# Gujjar Dairies Hisaab App

Is file ko repo ke root (`gujjar-dairies-app/`) mein `CLAUDE.md` naam se rakhein. Claude Code ye khud parhta hai.

## Kaun, kya
- Owner ki ek retail shop hai (milk, dahi, ghee, butter, bread, bun, cake, rusk, anday, bottles). Roz ka hisaab Excel sheet `JOHAR_SHOP_RETAIL_HISAAB.xlsx` mein hota tha (sheets: `ENTRY`, `FINAL HISAAB`). Ye app us sheet ki jagah le rahi hai.
- Owner technical nahi hai. **Owner se hamesha Roman Urdu mein, aasan alfaaz mein baat karo.** Code, commits aur comments English mein rakho.
- **Sab kuch free hona chahiye.** Koi paid service ya paid plan na lagao. Free tier ki limits batao agar koi hai.

## Maujooda halat
Static PWA, koi build step nahi. Files: `index.html` (HTML+CSS+JS sab ek file mein), `manifest.webmanifest`, `sw.js`, `icon-192.png`, `icon-512.png`.
- Data `localStorage` key `gd_hisaab_v2` mein (v1 wala `gd_hisaab_v1` safety ke liye chhoda hua hai, pehli baar khulne par v2 mein migrate hota hai). Har record par `u` (edit time ms), entries par `id` aur `del` (soft delete), items par `off`, `pru` (price edit time). `q` = upload ke liye baqi keys, `cur` = har table ka pull cursor, `me` = {email, role}.
- App khulte hi login page aata hai (`S.me` khali ho to). Login ke baad neeche tabs: Stock, Hisaab, Doodh, Bank, Cost, Report, Account (sync, staff manzoori, password, Backup, aur "Items, rate aur cost" ka button). Staff ko sirf Stock, Hisaab, Doodh, Account.
- Hisaab tab paper khaate (cashbook page) jaisa: kinds `ex` kharcha, `sl` salary (dono munafa mein), `cr` ghar aur gari kharcha (TOTAL PAID 2), `ud` udhaar diya (3), `bl` bill ki raqam / owner ko (4), `sp` supplier (5), `rc` cash wasool. Galla = opening + counter sale + rc + bank se nikala − sab paid − bank mein jama. Munafa = items munafa − ex − sl. Udhaar khata naam-wise: ud − rc (naam `nkey` se uppercase; "(375+375)" jaisa hissa naam ke aakhir mein hota hai aur khate mein hata diya jata hai). Raqam mein "900+900" likh sakte hain. Entry line-wise (`DR[date|kind]` drafts, sirf memory mein): naam ke saath datalist `dl<kind>` (us hisse ke pehle likhe naam), Enter naam→raqam→agli line (aakhir mein nayi line), neeche "Save karein" sab bhari lines save karta hai. Pichle kaam wale din ki entries naam ke saath aati hain aur raqam placeholder "Kal X" (`ph`) hoti hai; khaali chhodi line save nahi hoti, is liye agle din wapas nahi aati.
- Bank tab (sirf owner): `S.bk` = `ac` accounts {id,name,op} aur `tx` {id,day,ac,type,party,a,no,cd,st,note,del}. Types `BT`: jama (galle se bank, galla −), nikala (galla +), chq_diya, chq_mila, online_aaya, online_gaya. Cheque `pending` rehta hai jab tak "Clear ho gaya" na dabaya jaye; balance sirf `clear` wale ginta hai. Tables `bank_accounts`, `bank_tx` (owner-only RLS); queue keys `ba:`, `bt:`.
- Cost tab (sirf owner): `S.cs[itemId][day] = {c,u}`; kisi din ki cost = us din ya pehle ki aakhri tabdeeli, warna item ki shuru wali `cost`. Munafa `costOf(it,d)` se. Table `costs` (owner-only), queue key `cs:item|day`. Hisaab mein har entry par ✎ (naam/raqam badalna).
- Khata capture (tab `kc`, Stock/Hisaab ke upar 📷 button): 4 tak tasveerein (1800px JPEG) `/api/read-khata` ko jati hain, jo login check (`is_member` RPC, user ke token se) ke baad Google Gemini (`GEMINI_API_KEY` Vercel env, `GEMINI_MODEL` default gemini-2.5-flash, free tier) se JSON leta hai. `sure` wali values jo app se takrati nahi foran save; baqi sawal ban kar ek ek confirm hoti hain. Tasveer wali entries ke id `cp<yyyymmdd><kind><n>` (dobara parhne par wahi badalti hain). Chhapne wala form `khata-form.html` (P1/P2 stock 27 items fi page, P3 kharcha K1-K7) app ki items list se banta hai.
- Report: din ki tiles + "Stock ki raqam" (`stockVal`: closing ya opening × `costOf`), mahine ka card (`monthRows`), CSV download (`monthCsv`, BOM ke saath) aur WhatsApp share (`shareDay`/`shareMonth`, wa.me link).
- Production (tab `prd`, neeche ki patti mein apna button, owner+staff): `S.pr.rc` recipes {id,out item,ins:[{t:'it',id,q}|{t:'raw',name,unit,q,c}],off} — owner batch likhta hai: har saman ka `b` (kitna dala) aur recipe ka `y` (kitna bana, recipes.y column), q = b/y ek unit ke liye; `S.pr.d[day][recipeId]={q}` us din kitna bana. `sold()` = opening + pu + `made()` − us − `usedP()` − cl (delivery ka hissa sold ke andar hi rehta hai, `csold` alag karta hai). Laagat = shop items `costOf` + raw `c`; "Cost mein lagayein" us din se cost set karta hai. Tables `recipes` (owner likhe), `production`; queue keys `rp:`, `pd:day|recipe`. Seed recipes r_dahi (i2←i0), r_lassi (i10←i2,i0,CHEENI,BARF), r_bottle (i9←i0,CHEENI,PISTA,BADAM), miqdaar 0 — owner bharega.
- Employees (tab `emp`, Account se, sirf owner): `S.em` [{id,name,phone,start 'YYYY-MM',sal {'YYYY-MM':salary},off}], table `employees`, queue `em:`. Payment = Hisaab `sl` entry jis ka naam (`nkey`, "(..)" hata kar) employee ke naam jaisa. `emState`: pichla baqaya (shuru mahine se har mahine salary − diya) + is mahine ki salary − is mahine diya = dena hai (minus = advance). Salary ke chips/naam employees se.
- Fixed kharche (owner ke kehne par, tareeqa 2): `S.fx` [{id,name,amt {'YYYY-MM':mahine ki raqam},off}], table `fixed_costs`, queue `fx:` (Employees page par). `fixedDay(d)` = (fixed + employees ki salary us mahine) ÷ mahine ke din, har din ke munafa se katta hai. Hisaab `ex` mein fixed naam wali aur `sl` mein employee naam wali payment sirf galla kam karti hai (`exV`/`slV` munafa mein, `pl = prof − exV − slV − fxd`). Mahine ka munafa = din ke (pl + fxd) ka jod − poore guzre dinon ka fixed hissa (`monthSum`). Employee/fixed hatane par agle mahine se raqam 0.
- Items par `ord` (register ki tarteeb). Stock mein owner "Rate ✎" daba kar sirf us din ka rate (`rt`, day_stock mein) laga sakta hai, jaise anday ka roz ka rate.
- Doodh tab Google Sheet "MILK 2026 New" ki jagah le raha hai (plan: 1 entry ✓, 2 rate/raqam/payment/baqaya ✓, 3 milan + PNL + Suzuki kharcha ✓, 4 sync ✓, 5 sheet se purana data, 6 report/WhatsApp). Data `S.mk`: `ps` parties (`kind` 'sup' = doodh dene wali jaise Wasif Chacho, Bikri Bara; 'buy' = lene wali jaise Johar), `mr[day]` mandi rate {m,e} fi mann, `d[day][partyId]` = {bm,be,cm,ce,lm,le,sm,se} **kg mein** (1 mann = 40 kg; b bandhi, c cow, l mandi se liya, s mandi ko becha; m subah, e shaam). Party ka kul = b + c + l − s. Milan: dene wali parties ka kul = lene wali ka kul. Supabase tables `milk_parties` (sirf owner likhe), `milk_rates`, `milk_days`; queue keys `mp:`, `mr:`, `md:day|party`.
- Doodh raqam (sheet se mila hua, 20-21/10 ke 6 hisaab barabar): bandhi = mann × party ka bandhi rate, cow = mann × cow rate, mandi se liya = mann × (us waqt ka mandi rate − `l`), mandi ko becha = −mann × (mandi rate − `s`). Owner ke qaide: Wasif se 43 mann fixed (27 bandhi/full fat + 16 cow), upar ka mandi rate; Johar ko bhi 43 fixed + upar mandi rate; Bikri Bara mandi rate minus commission. `S.mk.pr[party][fromDay]` = {b,c,l,s} (pehla rate `2000-01-01` se, khali khana bharna usi daur mein, likha rate badalna dekhe gaye din se naya daur); `S.mk.ob[party]` = {v,d} purana baqaya d din ke aakhir tak (settings key `mob:<party>`); `S.mk.pay[day]` = [{id,p,a,n,del}]. Baqaya = ob + har baad wale din ki (raqam − payment); sup party ke liye musbat = hum ne dene hain. Tables `milk_party_rates` (sirf owner), `milk_pay`; queue keys `mpr:party|day`, `mob:party`, `mpy:day|id`. Staff payment likh sakta hai, raqam/baqaya/rate nahi dekhta. `pending` user ko "manzoori ka intezar" screen.
- Doodh Bill (owner, Doodh tab ka "Bill" chip): party + tareekh se/tak (`mbp`,`mbf`,`mbt`); `mstate()` = pichla baqaya, har din doodh/raqam/payments aur chalta baqaya; PDF `mbillPrint` (#prt), WhatsApp `mbillWA`. Party par `hk` (milk_parties.hk jsonb) = Hisaab entry naam jo us party ki payment ginte hain (`hkPays`, "(..)" hissa hata kar); ye `mamt().p` mein jud kar har jagah baqaya se minus hote hain. Owner "Rate aur purana baqaya" → "Hisaab se payment" mein chunta hai (Johar = dukaan, jaise ROZ RAQAM). `hk` mein `@bl` / `@cr` jaisi value poore Hisaab hisse ko jodti hai; Johar par owner ke kehne se `@bl` (Bill ki raqam / owner ko) aur `@cr` (Ghar aur gari kharcha) lage hain.
- Gaye ka doodh mandi ko becha alag line `g` (`gm`/`ge` kg, milk_days columns), bhains wala `s`. Commission: din ka apna `kc` (milk_days.kc, mandi rate mein + ya −), warna party rate `g` (milk_party_rates.gadj, kitna kam), warna bhains wala. Mandi se liya ek hi rate/commission par.
- Doodh marhala 3: `S.mk.x[day]` = {sz Suzuki kharcha, w farq ki wajah (kharab/ghar/ghalti/aur), n note}, table `milk_day_info`, queue key `mx:day`. Munafa (owner, Doodh tab ka "Munafa" chip) = lene wali parties ki raqam − dene wali parties ki raqam − Suzuki; sheet ki PNL se 20-21/10 barabar. Mahine ka total sirf aaj tak. Pichle 7 din mein jis din doodh nahi likha, Entry mein yaad dilata hai.
- Doodh marhala 5: sheet "MILK 2026 New" ka data 05/10 se 21/10/2026 tak Supabase mein dala (u=1000, payments id `sheet_<party>_<day>`, note "Sheet se"); purana baqaya 04/10 ke aakhir tak (Wasif 15,09,627, Bikri 61,160, Johar 0). Har din ka commission `k` (`milk_days.k`, sheet ka COMM, mandi rate mein jama/minus, us din ke liye aur becha dono par) owner kisi bhi din badal sakta hai; khali ho to party rate ka l/s lagta hai. 05-21/10 raqam, baqaya aur PNL sheet se barabar.
- Bandhi: party rate mein `qb`/`qc` (bhains/gaye bandhi, mun roz, subah-shaam aadha; milk_party_rates.qb/qc). Bandhi wali party par roz sirf asal doodh `xm/xe` (bhains) `ym/ye` (gaye) kg likha jata hai (milk_days columns); `mrow()` usse bm/be/cm/ce (poori bandhi), kam ho to sm/se ya gm/ge (mandi ko becha, commission ke saath), zyada ho to lm/le (mandi se liya) banata hai. Purane din (bm.. wale) waise hi chalte hain. Wasif aur Johar par 27/16 bhari hai.
- Doodh se dukaan ka stock: party par `si` (milk_parties.si, item id; Johar = i0 FULL FAT MILK). `milkIn(it,d)` = us party ka din ka doodh mun × 38 (`LPM`) litre, bhains+gaye dono; `sold()` mein purchase ki tarah judta hai (hath se likhi purchase ke ilawa). `costAt`: aisa din cost ki tabdeeli hai, cost = party ka din ka bill (`mamt().t`) ÷ litre; usi din Cost tab ki entry ho to wo jeet ti hai. Owner Doodh → party → Rate aur purana baqaya → "Dukaan ke stock mein" se badal sakta hai.
- Delivery tab Google Sheet "Milk Delivery Bill" ki jagah. Data `S.dl`: `cs` customers {id,name,addr,phone,op (app se pehle ka baqaya),ord,off}, `d[day][custId][itemId]` = {q,r,a,del} (q litre/ginti, dukaan ka doodh stock bhi litre mein hai, owner ne confirm kiya; r us din ka delivery rate; itemId `_amt` = sheet ki sirf raqam `a`, shop ke hisaab mein nahi ginti), `py` wasooli {id,day,c,a,m:'cash'|'online',note,del}, `sent[ym][custId]` (sirf is phone par, bill bheja). Har customer ka apna rate `cs.rates` {itemId: rate} (customers.rates jsonb; `rateFor(c,i)`; Bill page par "Is customer ka rate", naye customer mein doodh ka rate); trigger bhi pehle customer ka rate leta hai; rate badalne par is mahine ki likhi entries par lagana owner se poochta hai. Queue keys `dc:`, `dv:day|cust|item`, `dp:`, `bp:bill`. Din ka note item `_note` par {n} (deliveries.note column). Bill (WhatsApp/PDF) English mein: upar logo + `S.dl.bp` (shop, owner, phone, addr; settings key `bill`, sirf owner), Remarks column, neeche offers {t, img: chhoti JPEG data URL}. ## Hisaab ka logic (sheet se, isko na bigaro)
- Opening = pichle din ki closing (pehle din ke liye item ka `op`).
- Bika hua maal = Opening + Purchase − Closing. Closing khali ho to item ginti mein nahi.
- Sale = bika hua × rate. Item munafa = bika hua × (rate − cost).
- Galla: opening galla + sale + wasooli (rc) − kharche (ex) − customer/milk payments (cr) − supplier payments (sp) = hona chahiye. Asal cash in hand se farq = galla diff.
- Munafa/nuqsan = item munafa − kharche. Supplier payment stock ki kharidari hai, kharcha nahi.
- Original sheet mein ye bhi tha jo app mein abhi nahi: milk ka alag hisaab (litre se mann, sheet ke numbers se 1 mann = 38 litre lagta hai, e.g. 1723.3 litre = 45.35 mann; owner se confirm karo; `milk sale in mun`, purchase, closing), stock ki raqam (stock op/cl amount = quantity × cost), udhaar ka hisaab (HAJI UDHAAR, HAJI WASOOL), salary ka alag section, rent/utility aur labour ke alag head.

## Karne ke kaam (is tarteeb se)
1. **Pehle check:** `index.html` browser mein chala kar dekho (phone width par bhi). Koi bug ho to theek karo. Kuch bhi badalne se pehle owner ko ek line mein batao.
2. **Excel se milan:** `JOHAR_SHOP_RETAIL_HISAAB.xlsx` (owner se maango ya repo mein rakhwao) ke 25/04/2026 ke hisaab ko app mein daal kar dekho ke sale, munafa aur galla farq sheet ke barabar aate hain ya nahi. Farq ho to wajah batao.
3. **Online sync aur login (Supabase free plan):**
   - Email/password login. Sirf owner ke aur uske staff ke accounts.
   - Tables: items, day_stock, entries (ex/cr/sp/rc), cash. Har table par Row Level Security.
   - Offline-first rakho: entry pehle local, internet aane par sync. Conflict par last-write-wins chalega lekin kabhi data silently delete na ho.
   - Roles: owner (sab dekhe) aur staff (sirf entry, rate/cost aur report nahi).
   - Sirf anon/publishable key frontend mein. **Service role key kabhi commit na karo.** Keys Vercel environment variables ya config mein rakho aur owner ko batao kahan se milti hain.
   - Supabase free project 7 din inactivity par pause ho sakta hai. Owner ko ye batao aur roz use hone ki wajah se aam taur par masla nahi.
4. **Missing features:** milk ka alag hisaab, stock ki raqam, customer udhaar ledger (naam wise baqaya), salary section.
5. **Reports:** mahine ki report, Excel/CSV aur PDF export, WhatsApp par bhejne ke liye share button.
6. **Purana data:** purani sheets se history import karne ka tool.

## Usool
- Free stack hi. Naya dependency ya service lagane se pehle owner se poocho.
- Offline kaam karna band nahi hona chahiye. Service worker ka cache version (abhi `hisaab-v34`) badlo jab files badlein.
- Jab bhi kisi synced table mein naya column/field app mein parhna shuru ho, `index.html` ka `DATA_VER` ek barhao. Is se har device ek dafa saara data server se dobara parhta hai (warna purane version wala phone/computer wo field kabhi nahi le ga). Account mein "Sab data server se dobara layein" button bhi yahi karta hai.
- Maujooda `localStorage` data ko migrate karo, mita na do. Naye version se pehle Backup export ka tareeqa batao.
- Chhote chhote commits, aur har kaam ke baad `git push` taake Vercel deploy kare. Deploy hone par owner ko link batao.
- UI aasan rakho: bara text, ek haath se phone par chalne wali, Roman Urdu labels. Raqam `en-PK` format mein.
- Har badlav ke baad batao ke owner ko kya karna hai (aam taur par kuch nahi).
